# Instagram 投稿の品質チェック（納品前の関門）

依頼主（旅河さん）は「お客様（医院）に納品できる品質」を求めている。過去に次の指摘で差し戻された。同じ失敗を二度としない。

- 「全部同じ系統で、見る気が失せる」… 全投稿・全リールが同じレイアウトと同じ動きだった
- 「同じことを2度言っている」… 見出し・大きな数字・数字の説明・補足が同じ内容だった
- 「AI感が強い」「ダサい」… 教科書口調、整いすぎ、人の気配がない
- 「キャラクターが気持ち悪い」… 自作のキャラクターは使わない

**このチェックを通すまで、見本を送らない・デプロイしない・「できました」と言わない。**

## 手順

### 1. 自動チェック（エラー0件が必須）
```
python -X utf8 scripts/quality_check.py content/webmarketing.json --render --config config/genova.json
```
- E（エラー）が1件でもあれば直してやり直す。W（注意）は1件ずつ目で見て、直すか、直さない理由を言えるようにする
- 見ているもの: 1枚の中の重複、キャプション冒頭とタイトルの重複、となりの投稿と構成・デザインの型・リールの型・写真が同じ、分析画面の数字の使い回し、AIっぽい言い回し・絵文字・GENOVA、文字数、文字を縮めないと入らないページ

### 2. 一覧画像を作って自分で見る
- 全投稿の表紙を並べた一覧（プロフィールのグリッドのつもりで）… 同じ写真・同じ型が続いていないか
- 各投稿の全ページを横に並べた一覧 … はみ出し、空白だらけのページ、重なり、読めない文字
- リールは各型（screen / telop / photo）から最低1本ずつ書き出し、0.5〜3秒おきにコマを抜いて並べる … 動きがあるか、字幕が画面と重ならないか、最初の1秒で文字が出ているか

### 3. 別の目のレビュー（自分の判断に引っぱられないように）
サブエージェントに一覧画像とコマ画像だけを渡し、次の観点で点数（各5点）と具体的な指摘を返させる。結論は渡さない。
1. となりの投稿と見た目が違うか（単調さ）
2. 1枚の中で同じことを繰り返していないか
3. 文章が人の言葉か（教科書・AIっぽくないか）
4. 文字の大きさ・余白・重なり（スマホで読めるか）
5. 院長先生が保存したくなるか
どれかが3点以下なら直して、もう一度レビューする。
**新しいネタ（自動補充を含む）は、もっと厳しい採点表 `RUBRIC.md`（この同じフォルダ）で、全項目5点になるまで直す。**

### 4. ユーザーに出すとき
- 何をチェックして、何が残っているかを正直に書く（自動チェックの結果件数、レビューの点数、目で確認していない部分）
- 見本は、型の違いがわかるように並べて送る

## 文章のルール（書くときも直すときも）
- 1枚の中の見出し・数字・説明・補足・比較・吹き出しは、それぞれ別の情報にする（見出し=結論、補足=理由か具体例かやり方）
- 院長先生に話しかける口語。「重要です」「しましょう」「効果的」「最適化」などは使わない。絵文字なし
- 数字の効果を断定しない。分析画面の数字は「イメージ」と明記し、投稿ごとに内容に合わせて変える
- 医療広告ガイドライン（体験談・ビフォーアフター・比較優良・誇大）を勧めない
- 表紙は問いかけと言い切りを混ぜる（「〜ませんか？」ばかりにしない）
- 表紙の「3つ」「5つ」と中身のページ数を合わせる
- 文例・例え（「駐車場は医院の裏に3台」など）は投稿をまたいで使い回さない
- まとめ（summary）は見出しの写しにしない。行動の形の項目か、本文にない1行
- 各投稿に、保存したくなる実用の1枚（文例 template／表 table／数字の目安／チェック）を入れる
- 比較優良・最上級（No.1、最高など）は、根拠があっても医療広告では使えない
- ハッシュタグは1投稿5個まで（いまの Instagram の上限。時期は言い切らない）。キャプション生成も5個で切る

## 見た目のルール
- カルーセルの型（design）: note / color / photo を、となり同士が同じにならないように並べる。color 型は背景色（ピンク・紺・深緑）も切り替える
- リールの型（reel_style）: screen / telop / photo を、となり同士が同じにならないように並べる（機械的な順番のくり返しにしない）
- 地図・グラフなどの画面の図は、投稿ごとに中身（医院名・数字・グラフの形）を変える
- 表紙の人物は、女性・男性・年配の方が偏らないように並べる
- **同じ写真は2度使わない**。表紙・中のページ（page_photos）・リールのどこでも、投稿をまたいで1枚1回（依頼主の指示 2026-11-14）。足りなければ写真を追加で集める
- 写真は Pexels の実写（assets/photos/catalog.json）。人物は「イメージ」として使い、社員だとは書かない。中のページとリールは顔の写っていない写真
- 自作のキャラクター・イラストは使わない
- **写真の中に文字（英語の画面・ポスター・ロゴ・手書きメモ・案内板の数字）が写っていないか**、表紙・中のページ・リールの全部を一覧画像で目で見る。写っていたら差し替え、catalog.json の rejected に入れる
- 表紙は人物写真ばかりにしない。3〜4割は `cover_mock`（文例カード・地図・HP・数字の画面）にして、グリッドで写真と図が交互に見えるようにする
- 文例・表がある投稿は `cover_tag`（「文例つき」など）で、表紙から保存したくなる中身があると伝える
- 骨組みを散らす: `form`（qa / ng / steps / myth / case）を1〜2割、締め（summary）は check・one・template（文面で締める）・mark="x"（やらなくていいこと）を混ぜる
- 締めの一言（cta）は投稿ごとに書く。DM・コメント・共有・保存の誘い方と言い回しを散らす
- 背景の大きな番号など、飾りを見出しや本文に重ねない
- リール: 文字はカルーセルを縮めて載せず、要点だけを大きく（幅の6%前後）。まとまりを画面の縦の真ん中に置き、下20%（操作ボタンの範囲）は避ける。空のコマを挟まない
- 並び順: 同じ系統（マップ・口コミ・広告・SNS・採用など）は7本以上あける。GENOVA は config の schedule.order = "sequence" で並べた順に出る

## リールの読み上げ（AI音声）とツールの説明
- リールは全部 AI 音声で読み上げる（scripts/voice.py、edge-tts）。投稿ごとに `narration`（場面ごとの台本の配列）を書く。数は screen 型なら 1＋reel.scenes の数、それ以外は 1＋points の数＋1
- 台本は画面の字を読むだけにしない。画面にない理由・やり方・例・目安を足し、音だけで内容がわかるようにする。冒頭32字以内、各場面110字以内、合計200〜340字（約6字/秒、35〜55秒）
- 「点数」「表示回数」「管理画面」のように、どの道具のどの画面かわからない言葉を残さない。道具の名前をページに書き、キャプションに「ツール名：URL」を入れる（URL は開けることを確かめたものだけ）
- 「点数とは何？ツール？わかりにくい」「音無しだと入ってこない」は依頼主からの差し戻し（2026-11-14）

## 写真の割り当て
- `python scripts/assign_photos.py content/webmarketing.json` で、中のページとリールの写真を1枚1回で割り当てる（足りないと終了コード1）
