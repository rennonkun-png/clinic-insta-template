# 投稿ネタ1本のデータの書き方（content/*.json）

`content/webmarketing.json`（院長のための集患メモ、50本）の今の形をもとに、投稿ネタ1本の書き方をまとめたもの。
最初の制作仕様（SPEC.md）と読み上げの仕様（第15弾 NARRATION.md）、直しの指示（REVIEW 第1〜14弾）を、今のデータに合わせて整理し直した。
**古い指示と今のデータの形が食い違うところは、今のデータの形を正とした**（食い違いは各所に「※」で書いた）。

できたネタは、`.claude/skills/insta-quality-check/RUBRIC.md` の採点表で全項目5点になってから列に足す。

---

## 1. ファイルの形

- ファイルは投稿の**配列**。1つの要素が1本の投稿。
- **配列の順番＝投稿する順番**（config の `schedule.order` が `"sequence"`）。足すときは、採点表 B14 の並びの条件（同じ系統は7本以上あける、design・reel_style が続かない、写真の表紙と図の表紙がなるべく交互）を満たす位置に入れる。
- 読み書きは UTF-8。Python で読むときは `python -X utf8`。
- 文字の飾り（表紙・見出し・字幕・まとめ）: `*語*` は色付きの強調、`==語==` はマーカー（帯）。1つの見出し・字幕に強調は1か所まで。`\n` で改行位置を指定する（文節の切れ目で切る。単語の途中・助詞の前で切らない）。
- 「GENOVA」は投稿データのどこにも書かない（会社名・説明はキャプション末尾に設定から自動で付く）。絵文字・記号の飾り・「！」は使わない。

## 2. キー一覧

「必須」= 50本すべてにある。「場合」= 条件つき。

| キー | 必須 | 形 | 意味・書き方 |
|---|---|---|---|
| `id` | 必須 | 文字列 | 英小文字とハイフン（例 `gbp-basics`）。ほかの投稿と重ねない |
| `title` | 必須 | 文字列 | キャプションの1行目に出る題。16〜30字。言い切りすぎない・実例を装わない（採点表 A15） |
| `hook` | 必須 | 文字列 | 書き出しの種類。`question` / `number` / `warning` / `howto` / `myth` / `story` のどれか（集計 scripts/analyze.py で使う）。50本で偏らせない |
| `service` | 必須 | 文字列 | 紐づくサービスのキー。GENOVA では `"web_consulting"` |
| `illustration_prompt` | 必須 | 文字列 | 英語の絵の説明（古い画像生成用。今の描画では使っていないが、キーは残す） |
| `cover_lines` | 必須 | 文字列3つ | 表紙の大きな文字。3行。最後の行が一番言いたいこと（`==…==` で帯） |
| `lead` | 必須 | 文字列 | 表紙の下の一言。cover_lines と別のことを言う |
| `cover_text_pos` | 必須 | `"bottom"` / `"top"` | 表紙の文字を置く側。写真の顔にかからない側。迷ったら bottom |
| `cover_photo` | 場合 | パス | 写真の表紙のとき。`assets/photos/catalog.json` の `cover_people` から（7章） |
| `cover_focus` | 場合 | 0〜1 | 写真の表紙のとき、写真のどの高さを切り取るか（今は 0.3 か 0.5） |
| `cover_mock` | 場合 | オブジェクト | 図の表紙のとき（3章）。cover_photo とどちらか一方 |
| `cover_tag` | 任意 | 文字列 | 表紙右上の黄色い札。6字以内（3章） |
| `points` | 必須 | 配列 3〜5個 | カルーセルの中のページ（4章） |
| `form` | 任意 | 文字列 | 投稿の型。`qa` / `ng` / `steps` / `myth` / `case`（5章） |
| `summary` | 必須 | オブジェクト | 最後のページ（締め）（6章） |
| `caption_lead` | 必須 | 文字列 | キャプションの冒頭（8章）。道具を使う投稿は最後に「ツール名：URL」 |
| `body` | 必須 | 文字列の配列 | キャプション本文の段落（8章） |
| `cta` | 必須 | 文字列 | キャプションの締めの一言。40字以内（8章） |
| `hashtags` | 必須 | 文字列3つ | 投稿ごとのタグ。ちょうど3個（8章） |
| `design` | 必須 | `"note"` / `"color"` / `"photo"` | カルーセルの見た目の型。となりの投稿と同じにしない |
| `palette` | 場合 | 0 / 1 / 2 | design が color のときだけ。背景色（0・1・2 がピンク・紺・深緑のいずれか）。color の投稿どうしで切り替える |
| `reel_style` | 必須 | `"screen"` / `"telop"` / `"photo"` | リールの型。となりの投稿と同じにしない（7章） |
| `end_style` | 必須 | `"ask"` / `"save"` / `"recap"` | リールの締めの形。ask=問いかけ、save=保存を促す、recap=まとめの項目を出す |
| `reel` | 必須 | オブジェクト | リールの冒頭と場面（7章） |
| `narration` | 必須 | 文字列の配列 | リールの読み上げ台本（9章） |
| `page_photos` | 場合 | パスの配列 | 中のページとリールの写真。`scripts/assign_photos.py` が書く（11章）。手で書かない |

今は使っていないキー: `hook_photo`（古いリールの冒頭写真。チェックと描画は読むが、今のデータにはない）、`caption_extra`（キャプションの追記。今のデータにはない）。

## 3. 表紙

- `cover_lines`: 3行、各行11字以内（今のデータの最大11字。※SPEC は2〜3行だったが、今は全50本が3行）。問いかけと言い切りを混ぜる（「？」で終わる表紙は全体の45%以下）。表紙で答えを出しきらず、問いか数字で止める。数字を出せる投稿は具体的な数字を入れる。「◯つ」と書いたら、key を除いた points の数と合わせる。
- `lead`: 22字前後（※SPEC は22字以内、今のデータは11〜29字・中央18字）。
- 写真の表紙と図の表紙のどちらか。全体の3〜4割以上を図にして、グリッドで交互に見えるようにする（※R12 は「50本で20本」、今のデータは27本）。

### cover_mock（図の表紙）の type

| type | 書き方 | 使いどころ |
|---|---|---|
| `card` | `{"type": "card", "label": "星1への返信の文例", "text": "1〜3行の文例（改行は\n）", "angle": -4}` | 文例のある投稿。text はカルーセル内の文例と同じか要約（新しい文例を作らない。中のページと一字一句同じにはしない）。今のデータの text は22〜47字。50本で8本以内（※今のデータは10本） |
| `map` | `{"type": "map"}` | マップ検索の画面 |
| `profile` | `{"type": "profile", "good": false}` | マップの医院情報。good=false で古い情報（×）、true でそろった情報 |
| `chat` | `{"type": "chat", "question": "患者さんがAIに聞く文"}` | AIの答えの画面 |
| `dashboard` | `{"type": "dashboard", "title": "◯◯（イメージ）", "value": "4.2万円", "delta": "-8%", "kpis": [["項目","数字"]×3], "series": [12個]}` | 数字の画面。title に必ず「（イメージ）」 |
| `hp_bad` / `hp_good` / `hp_pair` | `{"type": "hp_bad"}` など | HPの画面（悪い例／良い例／2台並び） |

同じ type は50本で5本以内。

### cover_tag（表紙の札）
文例・表・チェック表がある投稿に付ける（50本で約15本。※今のデータは22本）。6字以内。今使っている札: 「文例つき」「表つき」「保存版」「チェック表」「メール文例」「添削つき」「穴うめ式」「題の例つき」「マップn/6」（マップの連載番号。並び順どおり、gbp-basics が 1/6）。同じ札は6本まで。

## 4. points（カルーセルの中のページ）

- 3〜5枚（※SPEC は4〜5枚だったが、R2 から3〜5枚。今のデータは3枚5本・4枚35本・5枚10本）。
- 同じ kind を続けない。1投稿で同じ kind を2回使わない（form の投稿は除く）。key は1投稿1枚まで。
- 保存したくなる実用の1枚（template・table・stat・check のどれか）を入れる。
- 1枚の中の見出し・数字・説明・補足・比較・吹き出しは、それぞれ別の情報にする（見出し=結論、補足 t=理由か具体例かやり方）。

### 全ページ共通のキー

| キー | 書き方 |
|---|---|
| `kind` | 下の表のどれか |
| `h` | 見出し。`\n` で2行（今のデータは全部2行）、各行10字以内。強調は1か所 |
| `t` | 補足。理由・具体例・やり方を1〜2文（今のデータは18〜87字・中央40字。※SPEC は60字以内）。必ず入れる。default・key・stat・voice では画面に出る。そのほかはキャプション・リール用で、画面には出ないことがある。25字未満で下が空くなら足す |

### kind ごとのカード

| kind | 足すキー | 書き方（数字は文字数の目安。括弧は今のデータの最大） |
|---|---|---|
| `default` | なし | 見出し＋補足 t がそのまま画面に出る |
| `key` | なし | 黒背景の結論ページ。t が画面に出る。1投稿1枚まで。最後を key で終える投稿は全体の半分以下 |
| `compare` | `ng`, `ok` | よくある悪い例とこうする。各26字以内（ng 26・ok 21）。比較のある投稿は全体の3割以下 |
| `stat` | `num`, `num_label` | num は4字前後（例「2〜3回」「15秒」）、見出しに書かない。num_label は「その数字が何か」だけ（20字以内）。t は数字の根拠か使い方。見出しの主張を裏づける数字でなければ使わない。掛け算だけの数字は使わない |
| `check` | `items`、任意で `mark` | items 3〜5個、各13字以内。「やってはいけないこと」の一覧は `"mark": "x"`（✕が付く）。避けることと足すことを混ぜない |
| `voice` | `voice_label`, `voice` | voice は30字以内の、よくある一言。voice_label は「よくある声（例）」「受付でよく聞かれる一言（例）」のように**（例）を付ける**（「患者さんの本音」と書かない）。吹き出しのある投稿は50本で15本まで |
| `qa` | `q`, `a` | q は院長が実際に言いそうな一言（18字以内、今は16）。a は50字以内（47）。見出しは答えの要点で、q と同じ文にしない |
| `template` | `label`, `text` | 文例。label は「そのまま使える文例」「自己紹介欄の例」など。text は `\n` で改行、120字以内（今は47〜84字）。日付は「○月○日（○）」の形（具体的な日付と曜日を組み合わせない）。ほかの投稿の文例と同じにしない |
| `table` | `rows` | 1行目が見出し行。列は2〜3。行は見出し行＋2〜4行（今は全部3行か4行＋見出し）。各セル14字以内（今は12） |
| `mock` | `mock` | 画面の図。`{"type": "map", "highlight": 0}` / `{"type": "dashboard", "title": "◯◯（イメージ）", "value": "1,180", "delta": "+6%", "kpis": [["項目","数字"]×3], "series": [12個の数]}` / `{"type": "chat", "question": "…"}` / `{"type": "hp_pair"}` など。全体の上限: map 2本、dashboard 3本、chat 1本、hp_* 1本。dashboard の数字はほかの投稿と同じにしない |
| `phone` | `ng`, `ok` | 予約ボタンが画面のどこにあるかの比較だけに使う（各18字前後）。全体で1本まで |

## 5. form（投稿の型）

points の番号の呼び方と、中身の約束が変わる。全体の1〜2割（50本で各型2本・計10本）。

| form | 番号 | 中身の約束 |
|---|---|---|
| `qa` | Q1, Q2… | すべてのページを `kind: "qa"`。院長がよく抱く疑問に1ページ1問で答える |
| `ng` | NG 1, NG 2… | すべてのページを `kind: "compare"`。「やりがちな失敗」集 |
| `steps` | STEP 1, STEP 2… | 実際にやる順番。見出しは動詞で始め、順番に意味があること |
| `myth` | 誤解1, 誤解2… | よくある思い込みを1つずつ正す。見出しは「〜は誤解」ではなく、思い込みと正しい考えがわかる形 |
| `case` | ケース1, ケース2… | 「開業1年目の場合」のような場面別。作り話の実例にせず、仮定で書く |

form を使った投稿は、表紙や lead も型に合う言い方にしてよい（例「院長からよく聞かれる5つの質問」）。

## 6. summary（最後のページ）

見出しの写しにしない。行動なら「誰が・いつ・何分で・どこで」まで具体的に（「見直す」「確かめる」だけで終えない）。`title` は10字以内（今は4〜9字）、中身に合う言い方（行動なら「次の一歩」、基準なら「迷ったときは」など）。同じ title は2本まで、「今日やること」は全体で5本以下。

| 形 | 書き方 | 目安の本数（50本） |
|---|---|---|
| チェック | `{"type": "check", "title": "院長と担当で分担", "items": ["行動の1文（20字前後、今は最大23字）", …3〜4個]}` | 残り（25本以下） |
| やらなくていいこと | `{"type": "check", "title": "見なくていい数字", "mark": "x", "items": [...]}` | 約6本。「やめていい・後回しでいい」が自然な投稿だけ |
| 1行まとめ | `{"type": "one", "title": "当てはまったら", "text": "次にやる1つのこと（28字以内、*強調*は1か所）", "note": "理由か目安を1文（40字以内）"}` | 約15本。note は必ず書く（ないと下が空く）。text は見出しの言い換えにしない |
| 文面で締める | `{"type": "template", "title": "受付での一言", "label": "そのまま言えます", "text": "2〜4行の文面（\n で改行）", "note": "使い方の一言"}` | 約8本。カルーセルに文例がある投稿で、中のページの文例を写さず締め用に短く |

※R2 の summary は `{"type": "check", …}` と `{"type": "one", …}` の2形だったが、今は4形。今のデータでは mark=x の締めも `"type": "check"` を書いている。end_style が recap のリールは、この summary の項目（template なら文面の行、one なら text）を締めに出す。

## 7. reel（リール）

```
"reel": {
  "hook": {"photo": "assets/photos/…", "focus": 0.3, "lines": ["1行目", "*2行目*"]},
  "scenes": [ 6〜7場面。最後は end ]
}
```

- `hook`: 冒頭の場面。lines は2行、各行9字以内。問いかけかドキッとする一言。photo と focus（0.25 か 0.3）は11章。
- `scenes`: 今のデータは6場面31本・7場面19本（※SPEC は5〜7）。各場面に `type` と `say`（画面上部の字幕。`\n` で2行、各行13字以内を目安。強調は1か所。end と text の say は1行でよい）、多くに `sec`（秒）。
- 実際の長さは、読み上げ（narration）が終わるまで場面が伸びるので、台本の長さで決まる（約35〜55秒）。※SPEC の「合計18〜28秒」は読み上げを入れる前の目安で、今は使わない。

### reel_style ごとの scenes の使われ方
- `screen`: reel.scenes が**そのまま全部**リールになる（スマホを操作して見せる動画）。
- `telop` / `photo`: リールの中身は points（各ページの見出しとカード）から作られ、reel.scenes からは **end の場面だけ**が締めに使われる。ほかの場面も書いておく（となりの投稿と場面の並びが同じでないかのチェックに使われるため）。

### 場面の type

| type | キー | 画面 |
|---|---|---|
| `type` | `query`（12字以内）、`say` | 検索窓に1文字ずつ入力。query はネタに合わせる（口コミの話なら「〇〇歯科 口コミ」） |
| `results` | `say`, `sec` | 地図付きの検索結果。type の直後に使う |
| `zoom_top3` | `say`, `sec` | 地図の3件に寄って赤枠。results の後 |
| `profile` | `good`（true/false）, `say`, `sec` | マップの医院ページ。false=情報が古い（×）、true=そろっている |
| `chat` | `question`（AIへの質問、30字以内）, `say`, `sec` | AIに聞くと医院名が返ってくる画面 |
| `hp` | `good`（true/false）, `say`, `sec` | 医院HPをスマホで開く。false=文字が小さく古い、true=見やすい・予約ボタンが上 |
| `dashboard` | `title`（「（イメージ）」を付ける）, `value`, `delta`, `kpis`（3項目、必須）, `say`, `sec` | 分析グラフが伸びて数字が数え上がる |
| `compare` | `ng`, `ok`（各24字以内）, `say`, `sec` | ✕と○のカードが順に出る |
| `text` | `lines`（2行、各10字以内）, `say`（20字以内）, `sec` | 大きな文字だけ。lines と say を同じにしない |
| `checklist` | `title`（12字以内）, `items`（3〜4個、各13字以内。英字の略語や長い製品名を避ける）, `say`, `sec` | 項目が1つずつ出てチェック |
| `end` | `lines`（2行、各9字以内）, `say`（22字以内。言い切る。「〜に」「〜を」で終えない）, `sec`、end_style が ask なら `ask`（30字以内） | 締め。end_style で形が変わる（ask=問いかけの吹き出し＋「コメントで教えてください」、recap=summary の項目、save=保存アイコン） |

※R14 で gbp-insights に `{"type": "map"}` の場面を使う案が出たが、`scripts/reel_screen.py` には map の場面がない（描かれない）。使わない。

### 組み立ての約束
- 最後は必ず end。同じ type を1本で3回以上使わない。
- スマホ画面系（type・results・zoom_top3・profile・chat・hp）と、それ以外（dashboard・compare・text・checklist）を混ぜる。
- ネタに合わない画面は使わない。字幕の話と画面に出るものを合わせる。
- 字幕で英字の略語（CVR など）を使わない。「・」が行頭に来る並べ方をしない。
- ask は内容に合った、答えたくなる具体的な問い。問いの形を投稿ごとに変える（「何と書いてありますか？」「いくつありますか？」「最後に直したのはいつですか？」）。

## 8. キャプション

`scripts/common.py` の `build_caption` が次の順に組み立てる:

1. `title`
2. `caption_lead`
3. `body` の段落（段落の間は空行。「・」で始まる段落が続くところは空行なしの箇条書きになる）
4. `cta`
5. 会社名と説明（config の clinic_name・footer_text。投稿データには書かない）
6. ハッシュタグ: 設定の固定2個（#クリニック集患 #院長のための集患メモ）＋投稿の `hashtags` 3個＝5個（Instagram の上限。5個で切る）

### caption_lead
- 口語の2文前後。1文目をタイトルの言い直しにしない。「〜ていませんか？」で始めるのは50本で8本まで。
- 長さは80字前後が目安（※SPEC は80字以内。今のデータは URL の行を除いて46〜123字・中央66字）。
- 道具を使う投稿は、最後に改行して `ツール名：URL` を1〜2行（10章の確認済み URL だけ）。道具を使わない投稿には足さない。

### body
- 2〜8段落（今は3段落が最多）。カルーセルに載っていない補足（理由・よくある場面・注意点）を書く。言い直しにしない。
- 院長が「うちもそう」と思う具体的な場面を1つ（時間帯・場所はほかの投稿と重ねない）。院長や受付の会話をそのまま引いた一文（「」）を1つ。段落は前の段落を受けてつなげる。
- 語尾は です・ます（体言止めの箇条は可、「〜する。」の常体は不可）。
- 50本のうち約12本は一部を「・」の箇条書き（3〜4行）、約5本は短め（2段落）。
- ほかの投稿を参照しない（「〜の投稿で」）。作り話の実例・数字を実際にあったように書かない。
- 言い切りの強さ（「直結」など）は依頼主が了承済みだが、事実の誤り・根拠のない数字・因果の言い切りは書かない。

### cta
- 40字以内（今は25〜39字）。その投稿の中身に合わせて書き分ける。売り込み口調にしない。
- 行動の種類（DM・保存・共有・コメント・その他）を散らす（DMは50本で15本以内、「〜に共有して〜してください」は5本以下、「お気軽に」は3本まで）。「保存して〜」は開く場面を具体的に。

### hashtags
- ちょうど3個。中身に合う、実際に使われている自然な日本語のタグ（例 #MEO対策 #口コミ返信 #医院ホームページ #歯科医院経営 #クリニック経営 #医療広告ガイドライン #リコール #無断キャンセル #医院の採用 #Googleマップ #LINE公式アカウント #リール動画）。
- 固定の2個と「GENOVA」を含むタグは入れない。50本で同じ3個の組み合わせを作らない。1つのタグは8本まで。

## 9. narration（リールの読み上げ台本）

リールは AI 音声（女性の落ち着いた声、やや速め。`scripts/voice.py`、edge-tts）で読み上げる。全投稿に必須。

### 数え方（数が違うとエラー）
- `reel_style` が `screen`: **1 ＋ reel.scenes の数**
  - [0] 冒頭（reel.hook.lines が出ている場面）
  - [1〜] reel.scenes の順。最後の end も1つと数える
- `telop` / `photo`: **1 ＋ points の数 ＋ 1**
  - [0] 冒頭（reel.hook.lines。なければ cover_lines）
  - [1〜points の数] 各ページ。画面には見出し h と kind に応じたカード（compare=×と○、qa=QとA、check=項目3つまで、stat=数字、template=文例の頭2行、table=3行まで）が出る。photo 型はカードがないページだけ t が字幕で出る
  - [最後] 締め（reel.scenes の end）

### 長さ
- 冒頭 [0] は32字以内。1〜2文で掴む（問いかけ・数字・よくある場面）。
- 各場面は1〜3文、110字以内。1場面1つの要点。
- 合計200〜340字（1秒に約6字で35〜55秒。今のデータは209〜308字）。

### 書き方
- 画面の字を読むだけにしない。画面にない「理由・具体的なやり方・例・数字の目安・どこを押すか」を足して、音だけで内容がわかるようにする。話の筋はその場面の画面と合わせる。
- 話し言葉の です・ます。院長に話しかける口調。「〜しましょう」連発、「いかがでしたか」「ぜひ」「重要です」「〜ことが大切です」を使わない。
- `*` `==` を入れない。英字はカタカナかことばで書く（Google→グーグル、HP→ホームページ、Instagram→インスタグラム、LINE→ライン、PageSpeed Insights→ページスピードインサイツ、Search Console→サーチコンソール）。数字はそのまま。
- 医療広告に触れる言い方（治療効果、比較優良、体験談の推奨）を入れない。
- 最後は cta かリールの end と同じ方向の一言で締める。毎回「保存して見返してください」にしない。
- 道具を紹介した投稿は、最後か該当の場面で「リンクはキャプションに載せています」と一言入れる。

## 11. 写真の割り当て

写真は Pexels の実写（`assets/photos/catalog.json`）。人物は「イメージ」として使い、社員だとは書かない。自作のキャラクター・イラストは使わない。**同じ写真は、表紙・中のページ・リールのどこでも、投稿をまたいで1枚1回。**

| 使う所 | キー | 選び方 |
|---|---|---|
| 写真の表紙 | `cover_photo`, `cover_focus`, `cover_text_pos` | catalog.json の `cover_people` から、内容に合い、まだどの投稿でも使っていない1枚。顔に文字がかからない側を cover_text_pos に。女性・男性・年配の方が並びで偏らないように |
| リールの冒頭 | `reel.hook.photo`, `reel.hook.focus` | 写真の表紙の投稿は cover_photo と同じ写真でよい。図の表紙（cover_mock）の投稿は、`cover_people` からまだ使っていない別の1枚 |
| 中のページ（design が photo）とリール（reel_style が photo） | `page_photos` | 手で書かず、`python scripts/assign_photos.py content/webmarketing.json` で割り当てる（`inner_laptop` / `inner_desk` / `inner_phone` / `inner_writing` / `inner_clinic` / `inner_charts` から、id に近い系統を優先し、表紙とも重ねない）。足りないと終了コード1 → 写真を追加で集める |

- page_photos の数: design が photo なら「points の数＋1」（各ページ＋締めのページ）、reel_style が photo なら「points の数」を後ろに足す。前半が中のページ用、残りがリール用。`null` の所は写真を使わない。
- 中のページとリールの写真は、顔の写っていないもの。
- 写真の中に文字（英語の画面・ポスター・ロゴ・手書きメモ・案内板の数字・他人のアカウント名）が写っていないか、描いた一覧画像で全部見る。写っていたら差し替え、catalog.json の `rejected` に入れる。
- 内容と合わない写真（暗い・古い・ぼけた、話と表情が合わない、投資の話に見える）は使わない。

※SPEC の写真カテゴリ（phone_woman / phone_man / family / laptop / analytics / clinic / worried、photo_catalog.json）は古い。今は上の catalog.json の分け方を使う。

## 12. 見た目の型の選び方

- `design`（note / color / photo）と `reel_style`（screen / telop / photo）は、となりの投稿と同じにしない。機械的な順番のくり返しにもしない（今のデータは design が note 17・color 18・photo 15、reel_style が screen 16・telop 18・photo 16）。

- `end_style` は ask / save / recap を散らす（今は ask 19・save 18・recap 13）。ask なら reel の end に `ask` を必ず書く。
